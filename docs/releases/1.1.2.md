# AssegaiPHP Beanstalkd 1.1.2

Beanstalkd 1.1.2 decouples application bootstrap from broker availability.

## What changed

- makes queue construction and `create()` configuration-only
- defers the Beanstalkd connection and tube selection until the first broker-backed operation
- leaves failed first-use connections uncached so later operations can retry after Beanstalkd recovers
- relies on Pheanstalk's reconnectable connection lifecycle after an established socket is interrupted
- wraps every enqueue failure from `Throwable` in the queue exception contract
- uses `localhost:11300` when host or port are omitted, matching the driver's documented defaults

## Compatibility

- requires `assegaiphp/common:^0.10.1`
- supports named application resolution through `assegaiphp/core:^0.10.1`
- remains compatible with `assegaiphp/console:^0.10.3`

## Upgrade notes

No application code changes are required. Existing `#[InjectQueue]` services can now be resolved while Beanstalkd is unavailable. A connection failure surfaces from the first `add()`, `process()`, or queue statistics operation that needs the broker, where the application or worker can report it appropriately.

Upgrade the coordinated stack together:

```bash
composer require assegaiphp/beanstalkd:^1.1.2 assegaiphp/core:^0.10.1 assegaiphp/common:^0.10.1 --with-all-dependencies
```
