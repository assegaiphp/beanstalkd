# AssegaiPHP Beanstalkd 1.1.1

Beanstalkd 1.1.1 repairs typed worker delivery and makes retry behavior consistent for every PHP failure type.

## What changed

- publishes jobs through Common's versioned JSON job envelope
- hydrates each reserved job against the processor's declared type, including legacy raw JSON messages
- reserves at most one job per `process()` call and returns an empty result after the configured `reserve_timeout`
- removes Beanstalkd's implicit `default` tube from named workers so a worker cannot reserve jobs from the wrong queue
- deletes jobs only after successful callbacks and releases decoding or processor failures with configurable retry priority and delay
- catches every `Throwable`, including `TypeError` and other `Error` implementations
- returns the hydrated job in successful and failed process results
- supports custom job codecs plus per-job publish priority, delay, and time-to-release options
- aligns the README with the current Assegai package format and documents typed processing and retry behavior without emoji headings

## Compatibility

- requires `assegaiphp/common:^0.10.1`
- intended to run with `assegaiphp/console:^0.10.3`
- legacy JSON objects remain consumable when the processor declares a compatible concrete job class

## Upgrade notes

Direct consumers that previously expected the raw JSON string must now accept the hydrated domain job object. Processors declared only as `object` receive `stdClass`.

The default `reserve_timeout` is `0`, allowing the console worker to observe an empty tube and apply its own sleep and stop options. Set a positive number of seconds when each driver poll should wait for work.

Failed jobs are released with `retry_priority` and `retry_delay`; configure a non-zero delay to avoid tight retry loops for transient failures.

Upgrade the coordinated stack together:

```bash
composer require assegaiphp/beanstalkd:^1.1.1 assegaiphp/common:^0.10.1 assegaiphp/console:^0.10.3 --with-all-dependencies
```
